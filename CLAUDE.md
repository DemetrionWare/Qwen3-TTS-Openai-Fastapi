# CLAUDE.md — Qwen3-TTS server, as deployed on this Vast box

Context for a Claude Code session that lands on this box after a reboot. The box is
**ephemeral (Vast.ai)** — hardware and public URLs change on every reprovision, but the
deployment contract below is stable. Re-derive anything marked *(runtime)* with the
listed command instead of trusting a value written here.

## What this is
OpenAI/ElevenLabs-compatible FastAPI wrapper around **Qwen3-TTS**, used **clone-only**.
The voice agent talks to the WebSocket `/v1/audio/speech/stream-input` path
(ElevenLabs-compatible, `ulaw_8000`): send reference audio, get the cloned voice back.
Cloning runs on **1.7B-Base**. Warm time-to-first-audio ≈ 0.65s.

- Repo: `DemetrionWare/Qwen3-TTS-Openai-Fastapi` @ `/opt/qwen3-tts-server`
- Process: `python3 -m api.main` (check: `ps aux | grep api.main`)
- Router with the WS + `_gpu_lock`: `api/routers/openai_compatible.py`
- Optimized backend (compile, cache, model-switch): `api/backends/optimized_backend.py`

## Boot chain
Vast `onstart` → `/root/onstart.sh` → clones `Ibrobot-org/llm-scripts-bootstrap` →
runs `qwen3-tts/vast-qwen3-tts-caddy-cloudflare.sh`. That script:
- clones this repo (fresh box) or `git pull --ff-only` (persisted volume),
- **generates the two files the server actually reads** (see below) via heredoc,
- starts the server, Caddy auth proxy, and a Cloudflare tunnel.

**Source of truth is the bootstrap script, not this checkout.** A fresh box re-clones
this repo from GitHub, so edits committed here that are not pushed to origin are lost on
reboot. The bootstrap script also regenerates `/root/.claude/CLAUDE.md` and the config
on every boot.

## The config the server reads — NOT the one in this repo
Active config: **`/root/qwen3-tts/config.yaml`** (= `~/qwen3-tts/config.yaml`).
It is generated by the bootstrap heredoc. The `config.yaml` committed in THIS repo is a
reference/example and is **not read** — editing it changes nothing. To change config
durably, edit the heredoc in the bootstrap script.

## Clone-only invariant — do not break
- Model list in the config is **`1.7B-Base` ONLY**. Do **NOT** add `1.7B-CustomVoice`
  or `0.6B`.
- Why: the backend does dynamic model switching. A non-clone request (e.g.
  `/v1/audio/speech` with a built-in voice like Vivian/Eric) maps to CustomVoice and
  forces unload → reload → max-autotune recompile (~90s), charged to the next clone
  call. Keeping CustomVoice out of the config makes it unloadable, so such requests fall
  back to the resident Base model and never swap.
- The `/v1/models` endpoint still advertises many OpenAI aliases (`tts-1`, `tts-1-hd`,
  per-language variants). Those are name aliases only — nothing else is loadable, so
  they resolve to the resident Base model.

## Concurrency
One `_gpu_lock` in `api/routers/openai_compatible.py` serializes all generation.
Concurrent callers queue; the 2nd concurrent caller's TTFB jumps to ~6s. Only relevant
if scaling past one caller — would need multiple workers or a batching backend.

## Ports
- `:11435` — TTS server (bound to `127.0.0.1`)
- `:11434` — Caddy auth proxy (public interface); Cloudflare tunnel front-ends this
- Public tunnel hostname is *(runtime)* and changes per boot.

## Runtime checks
- GPU / VRAM / that the model is resident: `nvidia-smi` *(GPU model varies per box;
  seen: RTX 4070 16GB, ~7.6GB resident)*
- Active model + optimization flags: `cat /root/qwen3-tts/config.yaml`
  (expect `default_model: 1.7B-Base`; optimization: `flash_attention_2`,
  `compile_mode: max-autotune`, `use_compile`, `use_cuda_graphs`, `use_fast_codebook`,
  `compile_codebook_predictor` all on)
- Loaded aliases: `curl -s http://127.0.0.1:11435/v1/models`
- Listeners: `ss -ltnp | grep -E ':11434|:11435'`

## Reference voice for latency testing

The production voice agent (keravada `customer-serv-phone`) clones from this pair, and
the remote latency numbers quoted to you were measured with it. It is committed here so
you can reproduce the **exact same request on the box itself** and split server time
from tunnel time.

- `tests/fixtures/voice.lauren.wav` — reference clip (347,402 bytes)
- `tests/fixtures/voice.lauren.txt` — its transcript

**Both are required.** Cloning is *ref-at-connect*: the server holds no voice profile, so
the clip and its transcript travel together in the opening config frame of every
connection. The `.wav` alone will not clone.

The client opens `/v1/audio/speech/stream-input/clone:<voice_id>` with an `xi-api-key`
header, then sends this config frame (`ref_audio` = base64 of the `.wav`, `ref_text` =
contents of the `.txt`):

```json
{
  "voice": "clone:Lauren",
  "voice_id": "Lauren",
  "language": "English",
  "response_format": "ulaw_8000",
  "x_vector_only_mode": false,
  "ref_audio": "<base64 wav>",
  "ref_text": "Hi there, I'm here to help with questions, support requests, and quick answers. All delivered with a calm, friendly, professional touch."
}
```

…then one or more `{"text": "..."}` frames (first with `"try_trigger_generation": true`),
then `{"text": ""}` as EOS. Audio comes back as base64 in `audio`, terminated by
`isFinal`. A stable `voice_id` is sent on every connection so the server builds the clone
prompt once and serves later connections from its warm cache.

**Measure time-to-first-audio-byte** — the gap between the last text frame and the first
frame carrying `audio` — not total wall time. That is the number that decides whether the
phone agent has dead air.

### Known gap (as of 2026-07-14)
Measured from a remote client over the public tunnel: warm TTFB is **flat at ~3.5–3.7s**
across 10 consecutive requests (min 3.50s, max 4.20s), against the ~0.65s warm target
above — roughly **6x off spec**. The WS handshake is a consistent ~0.4s, and the curve is
flat rather than climbing, so this is not the tunnel and not a cold clone cache; it is
generation speed. Run the fixture against `127.0.0.1:11435` and compare with the public
hostname to confirm how much (if any) of the 3.5s is the tunnel.
